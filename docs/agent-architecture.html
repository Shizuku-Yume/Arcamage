2

工具调用设计

Agent 不直接改写整张角色卡，而是通过受控工具进行结构化读写

接收用户任务

用户用自然语言提出需求，例如润色设定、整理世界书或补充角色信息。

选择必要上下文

Runtime 准备当前角色卡快照、Skills 内容和参考资料摘要。

模型决定工具

pi agent/LLM 根据任务判断需要读取字段、搜索条目或执行修改。

执行安全工具

工具执行器校验参数、字段路径和哈希后，对指定位置进行读写。

返回结果确认

系统展示工具调用轨迹、变更摘要和差异预览，便于用户检查。

card_* 普通字段工具

  • 列出角色卡字段结构
  • 读取指定字段片段
  • 设置字段值或文本补丁
  • 编辑数组类字段条目
card_read_field card_patch_text card_edit_items

lorebook_* 世界书工具

  • 查看世界书摘要
  • 搜索世界书条目
  • 读取或修改指定条目
  • 新增、删除、重排条目
lorebook_search_entries lorebook_patch_entry lorebook_upsert_entry

ref_* 参考资料工具

  • 列出用户上传资料
  • 按片段读取资料内容
  • 在资料中搜索关键词
  • 辅助设定补全与一致性检查
ref_list ref_read ref_search

skill_* 技能仓工具

  • 列出可用 Skills
  • 读取技能正文和引用
  • 新增或更新技能文档
  • 删除不再使用的技能
skill_list skill_read skill_upsert
设计重点：所有工具参数都经过白名单限制，字段路径会过滤危险 token，长文本修改优先使用补丁方式，世界书内容由专门的 lorebook 工具处理，从而降低误改整张角色卡的风险。

Skills 系统设计

将特定任务经验沉淀为可复用的 Markdown 技能文档

技能目录 catalog
→
技能文档 name / description / content
→
引用资料 references/*.md
技能选择机制 用户手动启用 + 根据指令关键词自动匹配
上下文构建器 控制总字符预算，裁剪低优先级段落，记录截断和忽略信息
注入 Agent Runtime 作为系统上下文影响模型行为，使任务流程更稳定
4

一次 Agent 运行时序

从输入到修改完成的典型执行路径

1. 用户输入 “请根据资料补充角色世界书，并优化开场白”
2. 收集上下文 当前角色卡字段 + 世界书摘要 + 启用 Skills + 参考资料列表
3. LLM 推理 判断需要搜索资料、读取世界书、修改相关字段
4. 工具循环 ref_search → lorebook_search_entries → lorebook_upsert_entry → card_patch_text
5. 校验与展示 检测宏和 HTML 标签保留情况，生成差异摘要并展示给用户
