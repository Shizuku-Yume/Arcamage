# system-prompt-guide

`system_prompt` 与 `post_history_instructions` 的写法。这两个字段是给模型的**行为指令**,不是剧情——管「怎么演」,不管「演什么」。

## 两个字段的分工

- **`system_prompt`**:角色定义之前/之上的总指令。设定整体扮演基调、输出规范、全局约束。
- **`post_history_instructions`**:插在对话历史**之后**的提醒。因为靠近生成位置,适合放「最容易被模型遗忘、需要每轮强化」的约束(如保持人称、不替用户行动、保持格式)。

> 两者都是可选的。简单卡可以都不写,靠 `personality` + `mes_example` 已经够稳。

## 写指令的原则

- **中立、第二人称对模型说话**:「你将扮演 {{char}}……」「始终保持……」。
- **聚焦行为约束,不写剧情**:具体剧情走向交给开场白和世界书。指令只管演绎方式。
- **短而聚焦**:几条清晰规则胜过长篇大论。指令越长,模型越容易抓不住重点或自相矛盾。
- **正面表述优先**:「保持 {{char}} 的口吻」比「不要不像 {{char}}」更可执行;但「不替 {{user}} 决定言行」这类边界用否定句更清楚。
- **不覆盖更高优先级约束**:指令不应试图绕过或弱化系统/平台的既有规则。

## 常用约束(按需取用)

```
- 你扮演 {{char}},以第一人称沉浸式回应,保持其性格与说话风格。
- 不替 {{user}} 决定其言行、想法或外貌。
- 推进剧情时给出新信息或新选择,避免原地复读。
- 保留并正确使用宏 {{user}} / {{char}}。
- (如有视觉/格式要求)按既定排版输出,保持每轮格式稳定。
```

## 保留约定

- 完整保留宏(`{{user}}`、`{{char}}` 等)与任何 HTML 标签。
- 优先 `card_patch_text` 局部增改,不要整段重写已有指令。
- 不改变用户已设定的核心人设与世界观。

## 何时用 post_history 而非 system

- 模型**前期听话、后期跑偏**(忘记人称、开始替用户行动、格式崩了)→ 把该约束放 `post_history_instructions`,因为它每轮都贴近生成位置强化。
- 全局基调、扮演框架 → 放 `system_prompt`。
- 同一条约束不必两处都写,选更合适的位置即可。
