# multi-greeting-strategy

`alternate_greetings` 多开场的差异化策略。多开场的价值在于给玩家**真正不同的入口**,而不是同一场景换几个词。

## 差异化的三个轴

设计多条开场时,沿这些轴拉开距离(每条主打 1-2 个轴):

### 1. 场景轴(在哪、何时)
不同地点/时间/事件:初遇现场 / 日常空间 / 危机时刻 / 特殊节日。
> 主开场在战场,备选开个在战后疗伤的营帐。

### 2. 关系轴(你们是什么关系)
同一角色、不同初始关系:陌生人 / 旧友 / 对手 / 恋人 / 上下级。
> 一条把 {{user}} 设为初识的委托人,另一条设为多年搭档。

### 3. 时间线轴(故事的哪个阶段)
平行或不同进度的故事线:认识前 / 关系破裂后 / if 线 / 多年后重逢。

### 4. 基调轴(情绪色彩)
同场景不同情绪入口:轻松搞笑版 / 严肃黑暗版 / 暧昧温情版,满足不同玩家偏好。

## 设计流程

1. 读 `first_mes`,明确它占了哪个场景/关系/基调,**备选要避开它已覆盖的区域**。
2. 决定每条备选主打哪个轴的差异。
3. 每条仍遵守「场景→登场→钩子」结构(见 `hook-patterns`),并保持角色内核一致。
4. 检查任意两条之间是否有实质区别,而非措辞不同。

## 一致与差异的边界

- **可以变**:场景、关系、玩家身份、基调、故事阶段。
- **不能变**:角色的核心性格、价值观、说话风格、世界观基本事实(除非是明确的 if 线设定)。
- 数量建议 2-4 条精而不同,胜过 8 条雷同。

## 与其他技能的分工

- **本技能 / opening-narrative-crafter**:负责每条开场「写什么、怎么勾人」。
- **frontend-presentation-optimizer**:负责给开场套视觉壳/状态面板。两者可叠加——先定叙事,再上视觉。
- **character-design-deepener**:多开场如果暴露了新设定,记得回头同步到 `description`/`personality` 并查一致性。

## 提示

- 新增用追加方式写入 `alternate_greetings`,不要覆盖现有条目。
- 每条末尾用一句话注明它设定在什么情境,方便用户挑选。
- 保留所有宏与 HTML 标签。
