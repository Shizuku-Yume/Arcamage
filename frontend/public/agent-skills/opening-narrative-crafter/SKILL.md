本技能专注于开场白的**叙事质量**(写什么、怎么勾住人),作用于 `first_mes` 与 `alternate_greetings`。它管「内容与节奏」;视觉呈现交给「卡面前端设计」技能,两者可叠加使用。

## 何时使用

- 用户想优化 `first_mes`,让开场更有代入感、更吸引人。
- 用户想新增/设计 `alternate_greetings` 多开场。
- 现有开场白平淡、信息倾倒、或没给 {{user}} 留下行动空间。

## 必须做

- 先读 `first_mes` 与现有 `alternate_greetings`,理解角色语气和剧情走向再写。
- 用 `hook-patterns` 设计开场:**场景代入 → 角色登场 → 留钩子给 {{user}}**。
- **给 {{user}} 留白**:开场结尾要有一个明确的、可回应的切入点(问句/动作/选择),不要把第一回合写满写死。
- 第一人称/视角与卡片既有风格保持一致。
- 多开场时用 `multi-greeting-strategy` 做差异化,避免几条开场雷同。
- 保留所有宏(`{{user}}`、`{{char}}`)与 HTML 标签。

## 不要做

- 不要在开场就信息倾倒(把整个世界观和人设一次性塞给玩家)。
- 不要替 {{user}} 决定其外貌、想法、台词或已做出的动作。
- 不要写成封闭独白,让玩家无从接话。
- 不要新增与角色设定冲突的事实。
- 多开场不要只改几个词了事,要有真正不同的情境/切入点。

## 工作流

1. 读 `first_mes` 与现有开场,确认语气、视角、剧情位置。
2. 从 `hook-patterns` 选一个适配卡片调性的钩子类型。
3. 写「场景 → 登场 → 钩子」三段,结尾给 {{user}} 留可回应的切入点。
4. 若做多开场,按 `multi-greeting-strategy` 拉开差异(场景/关系/时间线)。
5. 需要视觉壳时,叠加「卡面前端设计」技能;说明这条开场设定在什么情境。

## 示例

- 「开场太平淡,帮我改得更抓人。」→ 用「冲突中点」钩子,开在事件已经发生的瞬间,而非铺垫。
- 「再加两条不同的开场白。」→ 一条日常线、一条对立线,关系与场景都拉开。
