# entry-design

世界书单条目的设计:写什么、怎么插入。字段名对应卡片模型 `character_book.entries[]`。

## 条目内容写法

- **一条一主题**:一个地点、一个势力、一条规则、一个人物。便于精准触发,也便于后续维护。
- **信息密度高**:条目是按需注入模型上下文的,写成「事实条目」而非散文。要点清晰,避免铺陈。
- **自包含**:条目被触发时往往脱离上下文出现,内容要能独立读懂(必要时简短交代它是什么)。
- **篇幅克制**:长背景拆成多条互相关联的小条目,而不是一条巨长。

## 触发方式:constant vs 关键词

| | `constant: true`(常驻) | 关键词触发(默认) |
| --- | --- | --- |
| 行为 | 每次都注入上下文 | 仅当 `keys` 命中扫描文本时注入 |
| 适合 | 核心世界观规则、贯穿全程的硬设定 | 地点、配角、特定事件、按需细节 |
| 代价 | 持续占 token 预算 | 几乎不占,直到被触发 |

- 只把**真正需要全程生效**的少数条目设为 `constant`。
- `constant: true` 的条目可以没有 `keys`(允许空),不要因此删除它。
- 其余一律走关键词触发,把预算留给当前相关的信息。

## 关键插入字段

- **`keys`**:主触发关键词数组(详见 `keyword-strategy`)。
- **`secondary_keys`**:次级关键词,配合 `selective` 做「主词+次词同时命中才触发」的更精确控制。
- **`position`**:`before_char` 或 `after_char`——相对角色定义插入的位置。规则/世界观常用 `before_char`(先立框架),即时细节可 `after_char`。
- **`priority`**:预算紧张被裁剪时的保留优先级,越重要给越高。
- **`insertion_order`**:多条同时触发时的排列顺序。
- **`enabled`**:临时停用条目而不删除。
- **`comment` / `name`**:给条目起便于人类识别的备注/标题,不影响触发,推荐填写。

## 设计建议

- 先定哪些是 `constant`(尽量少),其余规划关键词。
- 规则类放 `before_char` + 较高 `priority`;花絮类放 `after_char` + 普通优先级。
- 用 `comment`/`name` 标注每条用途,方便日后维护。
- 改动后保留宏与 HTML 标签。
