# keyword-strategy

`keys` / `secondary_keys` 的选词策略。目标:**该触发时触发,不该触发时安静**。关键词是世界书最容易出问题的地方。

## 选词原则

- **要专不要泛**:选这个条目**独有**的词。「龙渊城」「赤鸦帮」好;「城市」「组织」「他」会到处误触发。
- **覆盖说法变体**:同一概念的常见叫法都列进去——全名、简称、别名、绰号。
  > 例:`["赤鸦帮", "赤鸦", "鸦党"]`
- **大小写/语言**:中文一般无大小写问题;若含英文专名,注意是否区分大小写(`case_sensitive`)。
- **数量适度**:每条 3-6 个关键词通常够。太多会增加误触发面。

## 避免触发冲突

- **检查重叠**:不同条目的 `keys` 不要互相包含。若「龙渊」同时是「龙渊城」和「龙渊剑」的关键词,二者会一起触发,造成信息打架。解决:用更完整的词(「龙渊城」「龙渊剑」),或配合 `secondary_keys` 区分。
- **避免高频词**:角色名、{{user}}、常见动词不适合做关键词——它们几乎每轮都出现,等于变相常驻。
- **泛词必须收窄**:不得不用某个常见词时,用 `selective` + `secondary_keys` 限定「主词且次词同时命中」才触发。

## secondary_keys + selective 的用法

当主关键词较泛、容易误触发时:

- 设 `selective: true`,把精确限定词放进 `secondary_keys`。
- 效果:只有 `keys` 和 `secondary_keys` **同时**命中扫描文本,条目才触发。
- 例:主词 `["剑"]` 太泛 → 加 `secondary_keys: ["龙渊", "传说"]`,只有谈到「龙渊剑/传说之剑」时才注入这条。

## 预算与扫描(Lorebook 级)

- **`scan_depth`**:向上扫描多少条消息找关键词。太浅会漏触发(刚提过的概念又消失),太深增加开销与误触发。一般保持默认,信息容易「断片」时再调高。
- **`token_budget`**:世界书注入的总 token 上限。条目多时,靠 `priority` 决定预算紧张时保谁。
- 把这两个理解为「灵敏度」与「容量」旋钮,默认值通常够用,出问题再调。
